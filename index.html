VIDEO PATH

Android 在设备端采集并用 MediaCodec 编码；iOS Simulator 在 macOS 上读取 IOSurface，由 VideoToolbox 编码。H.264 经 MPP1 与 DSH 认证 streaming Fetch 到达客户端，由 WebCodecs 解码；媒体中继层只转发字节。

⌘生命周期独立管理 DSH Host 插件 ↔ JSON-lines stdio ↔ Rust 会话、启动、状态与停止。实时输入无需排在启动等慢任务之后。

按平台接入原生能力

Android 的 Java bootstrap 仅准备 Looper 并加载 Rust。iOS Simulator 使用 macOS 系统框架，无需在模拟器中安装额外应用；不支持 iPhone / iPad 真机。

可追踪的会话边界

Android 连接绑定 adb transport ID；iOS Simulator 绑定具体启动实例。租约 generation 与采集 epoch 分开，过期输入被拒绝；显示几何变化会终止当前采集。

复用已有认证

客户端经 DSH 认证 HTTP 接口接收视频与提交有界输入批次，无需新增供浏览器直连的未认证监听端口。

BEFORE YOU CONNECT

运行环境

  • Apple Silicon · macOS发布目标为 darwin-arm64 Host。
  • Android：SDK platform-toolsHost 上可用的 adb，以及已授权的 arm64 Android 设备。使用 AVD 时另需 emulator 组件与现有 AVD。
  • iOS Simulator：完整 Xcode在同一台 macOS Host 上安装完整 Xcode 和运行时。本次归档已验收 Xcode 26.4 / iOS 26.4 的 iPhone 17。
  • DeepSeek HarnessWeb 或 Desktop；客户端需要 H.264 WebCodecs 支持。
DeepSeek 官方下载 ↗（新窗口）

使用自带运行文件的预览包，不需要安装 Rust、NDK 或 JDK。

01

取得并核对预览包

从项目 GitHub Release 取得 .tgz 与 SHA-256 文件；包内 runtime-manifest.json 记录版本、构建目标和运行文件摘要。用 shasum -a 256 核对下载文件与上方摘要。校验和用于完整性与溯源，不是代码签名。

02

安装、启用，再重启 Host

在插件管理器中添加本地归档，或使用 Web CLI。更换原生包版本后，重启 DSH Host，让新运行文件生效。

下载后，在归档所在目录运行以下命令。

dsh plugin --profile web add "$PWD/mobile-dev-harness-dsh-mobile-preview-0.1.0-preview.5-darwin-arm64.tgz"
Plugins→Add plugin→本地 .tgz

输入预览包的绝对路径，安装并启用。这个插件管理器流程也适用于 Web 界面。

03

打开面板，连接一个明确的设备

在聊天中打开移动设备面板，选择 Android 设备或 iOS Simulator，再点击 Connect。面板可见时自动预览；可点击、拖动或使用 Home。Back 仅支持 Android。

04

按需暂停，结束后断开

Pause 保持主动暂停，Resume 恢复。有效连接在面板隐藏后可恢复预览；租约过期需重新连接。断开不会关闭模拟器。

移除插件 +

先断开设备，再通过插件管理器移除。Web CLI 使用安装时的同一 profile：

dsh plugin --profile web remove @mobile-dev-harness/dsh-mobile-preview

当前边界

Know before you connect
PLATFORM

Android 与 iOS Simulator

发布目标为 Apple Silicon macOS Host。iOS 仅支持 Simulator，不支持 iPhone / iPad 真机；Linux / Windows 包未提供。Android API 29–37 是实现范围，不是全设备承诺。

INTERACTION

聚焦画面与基础输入

音频、录制、多点触摸、任意文本 / IME 和剪贴板集成未实现。iOS Simulator 当前限正向竖屏；旋转或显示几何变化会结束采集，需重新连接。

QUALIFICATION

持续补齐真实场景

Desktop 手动 App Switcher、旋转、其他 Xcode / iOS 运行时、更多 Android 厂商与长时间 GUI 运行仍需覆盖。当前不承诺固定帧率、延迟或所有设备兼容。

实现与运行的补充说明 +

Android API 29–33 使用 SurfaceControl / InputManager 路径；API 34–37 使用 DisplayManager mirror / InputManagerGlobal 路径。隐藏接口与厂商差异需要逐目标验收。

连接租约过期后需要重新连接；重启 adb server 后需重启 MPP Host。以下为 preview.3 的 Android 历史 GUI 记录，不代表 preview.5 通过：官方 Desktop 已验证系统窗口缩放、面板重开、暂停恢复和 GUI 卸载 / 重装。暂停及卸载后没有遗留 helper 或 adb reverse 映射，重新安装可恢复预览；Web API 37 已验证窄视口与宽视口切换无需手动启动。Web 在 API 35 连接后完成 GUI 卸载，设备入口与旧视图移除，插件依赖 / bundle、helper 和 adb reverse 均已清理；Web 在 API 35 重装、启用并重新连接后已恢复 Live 预览。操作系统最小化 / 后台返回、侧栏拆分 / 浮动及长时间运行仍需单独覆盖。

iOS Simulator 后端依赖 Xcode 私有接口，系统或 Xcode 更新后可能需要重新适配。本次归档限已验收的正向竖屏与运行时组合。定时原生手势打开 App Switcher 的结果已通过 Web 观察；这不等同于 Desktop 手动手势验收。取消或重置会释放已按下的触点，可能完成一次点击，并不等同于 UIKit 的取消事件。

MPP 参考 scrcpy 的视频与控制分离思路，但不运行、分发、依赖 scrcpy，也不兼容其通信协议。自动按手机比例调整侧栏宽度属于可选本地 DSH UI 扩展，尚不是上游公开 API。
